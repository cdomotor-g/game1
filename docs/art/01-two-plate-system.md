# 01 — The two-plate system

This is the single most important document in `docs/art/`. Everything else is detail
hanging off it.

## The requirement

The game ships in two visual modes:

- **Black-and-white** — for the print-and-play edition, home laser printers, photocopied
  reference sheets, and anyone who wants a cheap production run.
- **Colour** — for the retail box and the web build.

The requirement is that these are **not two versions of the art**. They are one piece of
art, printed twice, with one of the two plates left off.

## The model

Every image separates into two plates, in the literal printing sense.

```
          ┌──────────────────────────────────────┐
   z=2    │  INK PLATE      one colour: soot     │   all line, hatch, texture, type
          │                                      │   ALL INFORMATION LIVES HERE
          ├──────────────────────────────────────┤
   z=1    │  WASH PLATE     flat spot colours    │   category, mood, faction
          │                                      │   NO INFORMATION LIVES HERE
          ├──────────────────────────────────────┤
   z=0    │  PAPER          tallow #EDE4D1       │
          └──────────────────────────────────────┘
```

**Black-and-white mode is the ink plate printed alone.**
**Colour mode is the identical ink plate with the wash printed underneath it.**

The ink plate is byte-for-byte the same file in both modes. There is no black-and-white
adaptation, no "simplified for mono" variant, no separate export. One drawing, two print
runs.

## The two laws

### Law 1 — The ink plate carries everything

Every piece of information a player needs to play must exist on the ink plate. Colour may
*repeat* information. It may never *introduce* it.

If a card says "this affects food" by being ochre, the card is broken. It must say so
with an icon, a hatch, a label or a frame — and *then* it may also be ochre.

### Law 2 — The wash never speaks

The wash plate exists for category-at-a-glance, mood, and faction identity. Delete it and
the game is fully playable, merely less pleasant.

> **The test:** turn the wash layer off. If a rule became unreadable, the ink plate is
> unfinished. Fix the ink plate. Do not turn the colour back on and call it solved.

## Why this is not just an accessibility box-tick

Three independent reasons, and they all point the same way.

**It is the only honest way to get the user's stated requirement.** "The black-and-white
is the same in both, and the colour is just added" is a *separation* requirement, not a
styling preference. Any approach where the mono version is generated by desaturating the
colour version will fail, and here is the proof from our own palette:

Converted to greyscale, the eleven commodity category washes collapse into five clusters:

```
fuel 63   material 79   livestock 82   arcane 88   drink 98
                                    ...
raw 134   manufactured 139   food 148   luxury 150   textile 166   container 184
          ↑ ↑ ↑                          ↑     ↑
   within 5 levels of each other    within 2 levels
```

`material`, `livestock` and `arcane` land within nine of 255 levels. `food` and `luxury`
land within two. Desaturation does not produce a black-and-white edition; it produces an
unplayable one. The information has to have been in the line all along.

**It is free colour-blindness compliance.** Roughly one player in twelve cannot reliably
separate our oxide from our verdigris. Because no rule is ever carried by colour, there is
nothing for them to miss — the same property that makes the photocopy work.

**It makes the print run cheap and forgiving.** Registration tolerance on cheap board
stock is around 0.3mm. Art that depends on ink and colour lining up precisely looks broken
when it does not. Art where the line is self-sufficient looks *hand-printed* when the
registration drifts — which is the aesthetic anyway.

## The third plate: the slip

There is one deliberate exception, and it exists to make a scarcity visible.

**`slip`** is a duplicate of part of the wash, offset 0.6–1.2mm past the ink line so it
bleeds out from behind the drawing. It is permitted **only on arcane subjects**: mana
crystals, mana veins, arcane herbs, potions, the two arcane buildings, and arcane event
cards.

```
   normal subject              arcane subject
   ┌────────────┐              ┌────────────┐
   │▓▓▓▓▓▓▓▓▓▓▓▓│              │ ▓▓▓▓▓▓▓▓▓▓▓▓   ← wash escapes the line
   │▓▓ ink ▓▓▓▓▓│              │▓▓ ink ▓▓▓▓▓│
   │▓▓▓▓▓▓▓▓▓▓▓▓│              │▓▓▓▓▓▓▓▓▓▓▓ │
   └────────────┘              └────────────┘
     wash sits inside            wash is out of register
```

It obeys both laws. It carries no information the ink does not — arcane things are also
labelled, framed and hatched as arcane. In black-and-white mode there is no slip at all,
because there is no wash to slip, and nothing is lost.

Budget: **no more than 3% of the inked area** of any component, one offset direction per
component, consistent within a card.

## The layer contract

Any deliverable — hand-drawn, vector, or model-generated — must arrive with these layers
separable and named exactly:

| Layer id | Contents | Colour |
|---|---|---|
| `ink` | Line, hatch, texture, type, icons | `#1A1714` only |
| `wash` | Flat category and mood colour | Palette values only |
| `slip` | Arcane mis-registration | Palette values only |
| `grime` | Press artefacts, paper wear | `#1A1714` at low opacity |

In SVG this is four top-level groups:

```xml
<g id="wash">  <!-- flat shapes, no strokes --> </g>
<g id="slip">  <!-- arcane only, omit otherwise --> </g>
<g id="ink">   <!-- all line work, fill/stroke #1A1714 --> </g>
<g id="grime"> <!-- applied last, one strength --> </g>
```

Rendering black-and-white is then literally:

```js
doc.querySelectorAll('#wash, #slip').forEach(g => g.remove());
```

Note the z-order: `slip` sits *above* `ink` in the document so its escaped edge is visible
past the line, but it is masked to only appear outside the drawing. `wash` is always
bottom.

## Working checklist

Before any asset is considered done:

- [ ] Wash layer deleted — is every rule still readable?
- [ ] Printed at 100% on a mono laser printer — does it survive?
- [ ] Photocopied once from that print — does it still survive?
- [ ] Ink plate contains exactly one colour, `#1A1714`
- [ ] Wash plate contains only values from [`palette.json`](palette.json)
- [ ] No gradient, glow, soft shadow or blur anywhere on any plate
- [ ] Shifted the wash 0.3mm in any direction — does it still look intentional?
- [ ] Slip layer used only on arcane subjects, if at all

this, including how to separate a raster image that arrived as one flat picture.
